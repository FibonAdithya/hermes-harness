# Repo Registry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `hermes-wiki repos` command that writes `repos.md` and `repos-private.md` to the wiki daily, listing every repo with purpose, activity and its path on the laptop, hermes-vm and tig-adi.

**Architecture:** Three new modules in `wiki/hermes_wiki/`: `reposcan.py` collects facts (checkout scans over ssh, GitHub GraphQL, wiki pages), `repospage.py` turns facts into rows and Markdown (pure functions), `reposcmd.py` orchestrates, keeps a laptop-local state file and writes through the existing contents-API store. A systemd user timer on the laptop runs it daily.

**Tech Stack:** Python 3.11 stdlib (`tomllib`, `json`, `subprocess`), `gh api graphql`, `ssh`, bash/find/git on remote hosts, pytest.

**Spec:** `docs/ai/specs/2026-11-23-repo-registry-design.md` (approved 2026-11-23).

## Global Constraints

- Python stdlib only in the package; no new dependencies in `wiki/pyproject.toml`.
- Every shell-out (`gh`, `git`, `ssh`, `bash`) goes through an injected `run` with `subprocess.run`'s signature. Tests pass fakes; no test monkeypatches a default argument (wiki memory: a patched publish once hit the live wiki).
- Pages: `repos.md` frontmatter `type: log`, `tags: [coding]`; `repos-private.md` `type: log`, `tags: [coding, finance]`. Both bodies start with `<!-- Generated by hermes-wiki repos. Edits are lost; change ~/.config/hermes-wiki/repos.toml instead. -->`.
- Commit message for page writes: `repos: refresh`.
- Bands: `hot` (>= 20 commits in 30 days on the default branch), `active` (1-19), `dormant` (0), `lookup failed`. The raw count is never rendered.
- Purpose: max 160 characters.
- Never render a raw origin URL; only the `owner/name` slug parsed from it.
- Fail closed on privacy: wiki pull failure, unreadable pages, a private name in public text, or a secret pattern → exit 1, zero writes.
- Hosts (spec "Columns"): `laptop` (local, scan root `~`, find depth 3), `tig-adi` (ssh alias `tig-adi`, root `~`, depth 3), `hermes-vm` (ssh alias `hermes-vm`, names mode over `~/.hermes/sandboxes/docker/default/home/repos`, rendered `/root/repos/<name>`). ssh timeout 20 s. Skip dirs: `.cache`, `node_modules`, `Trash`, `.worktrees`.
- hermes-vm mirrors are matched by directory name, never by reading their git remotes. MEASURED 2026-11-23: `git -C <mirror> remote get-url origin` as user `hermes` fails with "detected dubious ownership" (mirrors are owned by root).
- hermes-vm mirrors supply paths only; they never cause a repo to be listed.

## Review Focus

1. A remote origin URL carrying a credential (`https://x-access-token:SECRET@github.com/o/r.git`) → only `o/r` reaches the page; `SECRET` never does. Test in Task 2.
2. ssh output that is empty, truncated, or prefixed by a login banner without the `root` header line → host treated as unreachable (state fallback), never as "no repos on this host". Test in Task 2.
3. A GitHub description or path containing `|`, a newline, or `[[x]]` → one table row, no injected wiki link. Test in Task 5.
4. GitHub owner listing that returns zero repos (token lost scope) → abort, zero writes, as `droplet/repo-sync.sh` does. Test in Task 6.
5. An origin on a non-GitHub host (GitLab, a local path) → treated as no origin ("local only"), not dropped and not mis-slugged. Test in Task 2.

### Task 5: Rows and rendering

**Files:**
- Create: `wiki/hermes_wiki/repospage.py`
- Test: `wiki/tests/test_repospage.py`

**Interfaces:**
- Consumes: `Checkout`, `GhRepo`, `PageRef`, `Overrides`, `HOSTS` from `reposcan`.
- Produces:
  - `@dataclass class Row: key: str; slug: str | None; purpose: str; pages: list[str]; band: str; last_commit: str | None; paths: dict[str, list[str]]; private: bool` — `key` is the slug or `local:<local_name>`.
  - `band(commits_30d: int | None) -> str` — `None` → `"lookup failed"`, `0` → `"dormant"`, `1..19` → `"active"`, `>= 20` → `"hot"`.
  - `build_rows(checkouts: list[Checkout], owned: list[GhRepo], extra: dict[str, GhRepo | None], index: dict[str, list[PageRef]], ov: Overrides, readme: Callable[[str], str | None]) -> list[Row]`. Listing: owned repos that are not fork/archived; plus non-hermes-vm checkouts whose slug owner is in `ov.clone_owners` (looked up in `owned` or `extra`; excluded if that `GhRepo` is fork/archived); plus non-hermes-vm checkouts with `slug is None` (key `local:<local_name>`, activity from the laptop checkout's count, else tig-adi's; pages matched by `local_name` lower-cased); plus `ov.include`; minus `ov.exclude`; `include` wins over fork/archived/exclude. hermes-vm checkouts attach to the row whose slug is `<owner>/<name>` for an owner in `ov.owners`, matched case-insensitively; unmatched mirrors are ignored. Two checkouts with one key merge into one row. Keys compare case-insensitively (`slug.lower()`); the row shows GitHub's `nameWithOwner` when known, else the first checkout's spelling. An origin of `github.com/fibonadithya/Talos` and a GraphQL `FibonAdithya/talos` are one row. Private: any `PageRef.private` among pages whose key equals the repo name lower-cased, or key in `ov.private`. Purpose order: `ov.purpose[key]`, the page named like the repo, else the first page alphabetically, then the GitHub description, then `readme(laptop_path)`, then `(no description)`. A public row's purpose that contains any private row's name (case-insensitive, word boundary) falls to the next source. Sorted by band order (hot, active, dormant, lookup failed), then `last_commit` descending (`None` last), then key.
  - `render(rows: list[Row], *, private: bool, today: str, host_notes: list[str]) -> str` — frontmatter per Global Constraints with `updated: <today>`, the generated-by comment, one line per host note, a table `| repo | purpose | activity | last commit | laptop | hermes-vm | tig-adi |`, and, on the public page only, a closing line `Private repos: [[repos-private]]`. Cells: `|` → `\|`, newlines → space, `[[` → `[ [`; page links rendered as `[[name]]` after escaping; multiple paths joined with `<br>`.
  - `private_names_in(text: str, rows: list[Row]) -> list[str]` — private rows' repo names found in `text` (case-insensitive, word boundary).
  - `same_page(a: str, b: str) -> bool` — equal ignoring the `updated:` line.

**Interfaces:**
- Consumes: Tasks 1-5; `freshness.maybe_pull`; `secretscan.find_secrets`; `todos.store_for`, `todos.update`.
- Produces:
  - `run_repos(cfg: WikiConfig, *, run, store, now: datetime, overrides_path: Path, dry_run: bool, out: TextIO, err: TextIO, sleep=time.sleep) -> int` — returns 0 (written or unchanged), 1 (aborted, reason on `err`, zero writes), 2 (bad overrides).
  - CLI: `hermes-wiki repos [--dry-run] [--overrides PATH]` (default `~/.config/hermes-wiki/repos.toml`), uses `subprocess.run`, `todos.store_for(cfg, run)`, `datetime.now(timezone.utc)`.
- Order inside `run_repos`:
  1. `maybe_pull(cfg.root, cfg.state_dir / "last-pull", now.timestamp(), interval=0, run=run)` when `cfg.pull`; a non-empty warning → exit 1.
  2. `load_overrides` (`ValueError` → exit 2); `page_index(cfg.root)` (`OSError` → exit 1).
  3. `since = now - timedelta(days=30)`; pass `since.strftime("%Y-%m-%dT%H:%M:%SZ")` to GitHub calls and `since.date().isoformat()` to `scan_host`. `owner_repos` for each `ov.owners` (`GitHubDown` → exit 1).
  4. `scan_host` for each of `HOSTS`. On `Unreachable`, use `state["hosts"][name]` from `cfg.state_dir / "repos-state.json"` and add host note `"<name> paths as of <date> (unreachable today)"`; with no saved state, add `"<name> paths unknown (unreachable today)"` and contribute no checkouts. A successful scan replaces that host's saved entry.
  5. `one_repo` for each clone-owner or include slug not in the owned list.
  6. `build_rows(..., readme=readme_line)`, split by `private`, `render` both with `today = now.date().isoformat()`.
  7. Abort (exit 1) if `find_secrets` hits either page or `private_names_in(public_text, private_rows)` is non-empty.
  8. `dry_run`: print both pages to `out`, write nothing (no store calls that write, no state file).
  9. Otherwise for `repos.md` then `repos-private.md`: `update(store, edit, sleep=sleep, path=..., create=True)` where `edit` returns `None` when `same_page(current, new)`; message `repos: refresh`. Then save the state file. Print `repos: wrote <n> page(s)` or `repos: unchanged`.
